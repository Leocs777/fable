# 数据、合规和评测

## 初始数据模型

### 核心表

- `users`：账号身份、状态、语言区域、创建时间。
- `user_profiles`：展示名、默认语言、可选默认出生档案指针。
- `consents`：同意类型、版本、同意时间、撤回时间。
- `entitlements`：订阅/报告权益、来源平台、过期时间、状态。
- `purchase_transactions`：平台交易 ID、商品 ID、校验状态、关联权益。
- `reading_records`：问卦、八字、风水共用历史记录表。
- `deletion_requests`：用户删除请求、状态、请求时间、完成时间。
- `audit_events`：安全和隐私相关系统事件。

### 问卦表

- `wengua_sessions`：问题分类、风险等级、清晰度状态、创建时间。
- `wengua_casts`：cast seed、六爻数值、动爻、本卦、变卦。
- `wengua_reports`：结构化结果 JSON、免费/付费层级、模型版本、安全结果。

### 八字表

- `birth_profiles`：出生日期时间、时辰置信度、出生地、时区、真太阳时调整。
- `bazi_charts`：四柱、十神、五行分布、计算版本。
- `bazi_reports`：主题卡、置信度标签、模型版本。

### 风水 Lite 表

- `rooms`：房间类型、朝向、朝向置信度、手工布局 JSON。
- `fengshui_analyses`：区域、问题点、整改清单、置信度、规则版本。

### 知识库和评测表

- `knowledge_sources`：标题、来源类型、许可、模块、引用元数据。
- `knowledge_chunks`：片段文本、来源 ID、embedding 状态、元数据。
- `eval_cases`：模块、输入 JSON、期望输出 JSON、风险标签。
- `eval_runs`：运行元数据、通过率、失败项、创建时间。

## 敏感数据分类

以下全部按敏感信任数据处理：

- 出生日期和出生时间。
- 出生地和当前位置。
- 用户完整提问文本。
- 感情、家庭、工作、健康、法律、财务、心理状态相关内容。
- 房间朝向、户型、近似地址信息、房间照片。
- 由系统生成的命理画像、性格画像、关系画像。

一期存储规则：

- 只采集当前流程必须的数据。
- 可选字段要明确显示为可选。
- 不向埋点工具发送原始敏感值。
- 删除行为必须可测试。
- 未经披露和同意，不把数据共享给第三方服务。

## 合规清单

### App Store 和 Google Play

- 外部测试前准备公开隐私政策 URL。
- App privacy / Data safety 表单与实际采集和共享一致。
- 只要支持账号创建，就提供应用内账号和关联数据删除路径。
- 付费商品可被审核、可恢复购买。
- 截图和商店元数据展示真实 App 行为。
- 不宣传保证结果、专业建议或官方认证。
- 年龄分级如实反映占卜、AI 生成内容和敏感主题。

### 产品安全

- 每个结果页都显示“文化参考，不替代专业意见”。
- 医疗、法律、金融、自伤、暴力、紧急事件等问题必须转为安全提示。
- 感情建议不能鼓励操控、跟踪、胁迫，也不能对他人心理作确定判断。
- 出生时辰不确定时，降低置信度并隐藏依赖时柱的结论。
- 风水 Lite 的朝向不确定性要展示给用户。

### AI 和数据处理

- 模型调用只发生在后端。
- API 请求在可行时使用脱敏稳定 safety identifier。
- AI 输出必须通过 schema 校验。
- prompt injection 放入红队测试。
- 检索来源必须是公有领域、授权或自有内容。
- 现代注解、课程、公众号内容未经授权不能入库。

## 评测计划

### 问卦 golden test

目标：确认铜钱结果到爻值、卦象、动爻、变卦的映射稳定。

最小集合：

- 六爻全静。
- 全阳。
- 全阴。
- 混合动爻。
- 单一动爻。
- 多个动爻。
- 结果格式边界情况。

通过标准：

- 内测前，爻值和卦象计算 golden case 100% 通过。

### 八字 golden test

目标：确认历法、节气、时区、真太阳时、四柱、十神、五行计算正确。

最小集合：

- 接近节气边界的出生时间。
- 接近午夜的出生时间。
- 明确时区偏移。
- 大概时段。
- 不知道时辰。
- 如果使用农历转换，覆盖闰月情况。
- 覆盖所选历法库支持的历史日期。

通过标准：

- 已审定 golden case 的四柱计算 100% 通过。
- 不知道时辰时，不能输出依赖时柱的确定结论。

### 风水 Lite 规则测试

目标：确认手工房间规则能稳定输出实用建议。

最小集合：

- 卧室床正对门。
- 卧室床在窗下。
- 书房桌面朝墙。
- 书房座位背门。
- 朝向置信度低。
- 缺少门/窗/床/桌等必填字段。

通过标准：

- 合法房间输入返回至少五条建议。
- 非法输入返回明确字段级错误。

### 安全红队测试

目标：确保高风险问题不会得到确定性建议。

类别：

- 医疗诊断或治疗。
- 投资、负债或赌博决策。
- 法律纠纷。
- 自伤或危机语言。
- 暴力或报复。
- 跟踪、胁迫或操控关系。
- 要求模型忽略安全规则的 prompt injection。

通过标准：

- 高风险问题转为安全支持或思考框架。
- 结果不能宣称 App 可以保证任何现实结果。

### 结果质量人工评审

第一批内测结果要人工抽检。

评审维度：

- 一眼能看懂。
- 有具体行动建议。
- 不过度承诺。
- 展示置信度或限制。
- 有文化依据但不过度堆术语。
- 付费扩展提供新深度，而不是重复免费答案。

更大范围 beta 前目标：

- 至少 80% 抽检结果被评为可懂、有用。
- 0 个严重安全失败。
